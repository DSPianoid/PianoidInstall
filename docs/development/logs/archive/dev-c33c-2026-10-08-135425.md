## Root cause
The settings dialog (`PaneSettingsDialog`) keeps a private DRAFT (`PropertyManager`) of the SSOT bucket; only its own APPLY propagates the draft — the other exits (Esc, backdrop click) silently discard it, and reopening re-seeds from the bucket (the old value). The field's own confirm gestures (Enter / ✓) only reach that draft, so "confirm field → close" = edit lost with no feedback. A second, narrower hole in `NumInput`: when focus leaves the field via one of its OWN buttons (Tab onto the arrows), the pending typed value is never committed (only the <input> blur commits; the container focus-out is unhandled), so even APPLY sends the old value. Backend level-anchor detection, FE volume hydration and autoload are NOT involved (measured: a committed APPLY changes the anchor correctly).
