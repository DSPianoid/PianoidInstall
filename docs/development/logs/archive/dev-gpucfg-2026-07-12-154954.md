Created `tools/gpu_rt_config.ps1` — the single implementation of apply + persistence:
- `-Status` (no admin) — clock vs ceiling, p-state, util, and whether the boot task is armed
- `-Apply` (admin) — derives max SM/mem clock dynamically, `-lgc max,max` (hard-fail) + `-lmc max,max`
  (graceful — unsupported on some GeForce/driver combos), prints BEFORE/AFTER
- `-Install` (admin) — registers Scheduled Task `PianoidGpuRtConfig`: **AtStartup, SYSTEM, RunLevel Highest**
  -> no logged-on user needed, no UAC prompt at boot
- `-Uninstall` / `-Reset` — back out the task / the lock
- **Boot-readiness retry loop** (`Wait-ForDriver`, polls up to 120 s): an AtStartup task can fire BEFORE
  nvlddmkm/NVML is up, in which case a naive script silently does nothing. This is what makes the
  persistence actually reliable.
- Boot runs (no console) append to `%ProgramData%\Pianoid\gpu_rt_config.log` -> operator-verifiable.

Supersedes `tools/lock_gpu_clock.bat` / `unlock_gpu_clock.bat` (manual-only, no persistence). Left in
place, not deleted — recommend removing them on approval to avoid two implementations of the same lock.

`check-gpu-clock.ps1` (root, mirrors its `check-*.ps1` siblings):
- **Discriminator:** `clocks.sm >= 0.95 * clocks.max.sm`. Sound at launch time *because* a locked GPU
  holds its ceiling EVEN AT IDLE (that is what `-lgc min=max` does — and it is exactly the idle-power
  cost that made the always-on boot task worse). An unlocked idle card sits far below. nvidia-smi exposes
  no direct "is a lock active" query on GeForce — I checked `--help-query-gpu` and the full `-q`; there is
  none — so this is the check, and the reasoning is in the file.
- Locked -> **silent, zero output, exit 0**. Not locked -> prints WHY (attributable: the operator must not
  get a bare UAC box from double-clicking a piano icon), then ONE `Start-Process -Verb RunAs` on the
  worker's `-Apply`, `-Wait`, then **re-reads the clock from the driver** rather than trusting the exit code.
- **UAC declined -> catch, warn, `exit 0`. NEVER blocks the app.** No exit-30 path at all (the CUDA check's
  abort code is deliberately not used here).
- Opt-out `PIANOID_SKIP_GPU_CLOCK_CHECK=1` (honoured in BOTH the .bat and the .ps1) — so a user who
  deliberately wants stock boost is never nagged.
