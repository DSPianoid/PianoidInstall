## Data-model decision — Hammer / Bow
- Storage unchanged: `model_parameters.excitation_mode = {"bow": [pitch,...]}` IS a per-pitch binary (set encoding; absent = hammer). No migration, no preset rewrite, gpufit `_drop_key` (Basic) and thump `bowed_keys` (engine read) unchanged.
- Exposed as an ordinary per-pitch parameter kind `excitation_mode` on the generic routes: GET /get_parameter/excitation_mode/<key_no> -> {"pitch": 0|1}; POST/WS set_parameter excitation_mode {pitch: 0|1} (mixed per-key map, one edit) or {mode: 0|1} for every key of key_no. Owner excitation_modes.py (commit_modes -> edit_commit: read-only guard, rule excitation_mode.modes, state_changed, one undo step) -> set_engine_excitation_modes (engine + thump refresh). Velocity map is per-pitch x128 and only read at a BOWED note-on, so it follows the engine mode with no change.
- FE: one store useBowParams holds {pitch: {speed, force, position, tilt, excitation_mode}}; groupe "Bow" registered like "Mass" (pitch axis over availableNotes).
