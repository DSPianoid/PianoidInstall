Converter declares the setting (its concern: describing the conversion).
Design decisions:
- G(p) = R/(rho_p*dx_p^2) * (n_ref/n_p)^k, physical mode; G=1.0 exactly in legacy. R = rho_60*dx_60^2 FROZEN at first load (persisted in model_parameters) so (a) p60 is bit-identical to legacy at load => c and the p60-calibrated output_scale keep their meaning (analytic re-derivation factor = exactly 1), (b) a later rho/dx edit at ANY pitch incl. p60 changes only that pitch (a dynamic p60 reference would rescale the whole keyboard on a p60 edit and fail the p60 single-pitch control).
- n_ref = strings of the reference pitch; k = unison_split_exponent in [0,1] (1 = physics, 0.5 = FPGA legacy shape_256 host convention, 0 = no split).
- Default string_gain_model = physical for presets without the field (user preference); legacy = bit-identical old coefficients.
- FPGA converter declares physical + k=0 for F15 (derivation in the session report; to be confirmed by measurement).
