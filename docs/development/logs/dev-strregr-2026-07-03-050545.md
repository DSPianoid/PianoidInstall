**ROOT CAUSE (measured):** `update_pitch_physical_params_GRANULAR` (parameter_manager.py:520)
calls `self._upload_excitation_coefficients()` = `CoefficientCache.seed()` — a FULL excitation-
coefficient rebuild (~206ms) — UNCONDITIONALLY on every granular string-physics edit, once PER
pitch in the caller loop (update_parameter:814-816).

MEASURED (dev-strregr-timing-probe.py, scratchpad_multi.py, scratchpad_whichparam2.py):
- single tension edit = ~207ms; standalone seed() alone = ~206ms (⇒ the edit cost IS the rebuild)
- coeff_cells_changed = 0 for EVERY strings-panel param (tension, stiffness→jung, damping→gamma,
  radius, density, length, hammer_position) — the rebuild is a byte-identical NO-OP
- 12-pitch (octave) edit = 2526ms (206ms × 12) ⇒ "no effect at first, then a delayed jump"
- offline apply is deterministic + reversible (baseline==restore, repeat-apply identical) ⇒ the
  physical tension slot itself applies correctly; only the redundant rebuild is wrong

WHY it's a no-op: coeff = c·mass·speed/(temporal·spatial). Factors: c=global calibration,
mass=hammer_mass, speed=velocity, temporal=level_impulse(excitation curve via excitation_length/
excitation_factor — model params, NOT string physics), spatial=hammer_spatial_impulse (hammer
geometry). NO string-physics param feeds any factor.

BISECT: the `_upload_excitation_coefficients()` call on the granular path was added by the
dev-excenergy series (b5585cf/f47829a/fc16fa3) — that is the introducing change. dev-normfix
(0fc6ef3) changed the coeff formula (product→division) but did not add/alter this call.
